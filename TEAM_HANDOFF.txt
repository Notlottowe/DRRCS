DATA USED BY BOTH PARTS

CloudAPI.call(command, data) sends requests to POST /api. For example:

    {"command": "incidents", "data": {}}

The client supplies the project key and, after login, the session token.

Domain records are stored in the D1 records table with these columns:

    kind, id, data, version

data is JSON. Existing examples are in backend/sample_data.json.

Important fields:

    assignments: incident_id, responder, status
    requests:    incident_id, resource_type, quantity, status, created_at
    allocations: incident_id, resource_id, quantity, status
    resources:   kind, total, available, allocated, consumed
    shelters:    manager, capacity, occupancy, status

Use timezone-aware ISO timestamps in backend data. UI time fields are UTC
and use YYYY-MM-DD HH:MM. Locations are [latitude, longitude]. Rectangular
boundaries are [south, west, north, east].

Send the current version when updating a record. Use write() to build record
changes and commit() to save the changes with audit and history in one batch.
Add new record categories to KINDS and any queries that need to read them.

Incident closure releases assignments, returns reusable resources, records
consumable use, and handles open requests. New allocation and request code
must use the same fields and status values as close().


RUNNING AND DEPLOYING

Follow README.txt to run the desktop client. Local UI changes take effect
when the app is restarted. Backend changes take effect after deployment.

The current API is https://drrcs-cloud-console.pages.dev
The Python Worker is drrcs-phase4-api.
The D1 database is drrcs-phase4-data.
gateway/ forwards requests to the Python Worker.
Keep the Cloudflare-provided address; do not add a custom domain.

The source ZIP does not include credentials. Ask for client.json and the
classroom login details separately.

The owner's deployment files are in DRRCS-owner-private beside the project
folder. DRRCS_OWNER_DIR can point to a different location. Keep the existing
password pepper when updating the current backend.

The project owner can deploy using:

    python3 deploy_cloud.py --wrangler /path/to/wrangler --pages-gateway

A different Cloudflare account needs its own Worker/database configuration
in the two wrangler.toml files and a separate initial setup.


BEFORE MERGING

1. Check the new normal and alternate flows against P2 and P3.
2. Check that new incidents, assignments, requests, and allocations appear
   correctly in incident closure, the dashboard, and reports.
3. Run python3 run_tests.py and review failures before merging.
4. Walk through the UI with each role, including invalid input and sign-out.
5. Finish the screenshots, meeting/progress records, and demonstration details
   required by the instructor.

The new UI has not yet completed a full interaction check for every role.
